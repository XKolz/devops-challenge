    Infrastructure

    All resources are managed by Terraform. No manual AWS console steps are required.

    Module structure

    terraform/
├── main.tf          ← provider, module calls, ECR, CloudWatch
├── variables.tf     ← all input variables
├── outputs.tf       ← ec2_public_ip, ecr_repository_url, vpc_id
└── modules/
    ├── networking/  ← VPC, IGW, subnet, route table
    └── ec2/         ← instance, IAM role, security group, user_data

    The root main.tf is intentionally thin — it wires the two modules together and owns resources that span both (ECR repository, CloudWatch).

    networking module

    Inputs:

    Variable Default Description
    app_name — Resource name prefix
    environment — Environment suffix
    vpc_cidr 10.0.0.0/16 VPC CIDR block
    subnet_cidr 10.0.1.0/24 Public subnet CIDR
    az us-east-1a Availability zone

    Outputs: vpc_id, public_subnet_id

    Resources created:

    • aws_vpc — DNS hostnames and support enabled
    • aws_internet_gateway — attached to the VPC
    • aws_subnet — map_public_ip_on_launch = true
    • aws_route_table — default route to IGW
    • aws_route_table_association — links subnet to route table

    ec2 module

    Inputs:

    Variable Default Description
    app_name — Resource name prefix
    environment — Environment suffix
    subnet_id — From networking module output
    vpc_id — From networking module output
    instance_type t3.micro EC2 instance type
    key_name required Existing key pair name

    Outputs: instance_id, public_ip

    Resources created:

    • data.aws_ami — latest Amazon Linux 2 HVM AMI (dynamically resolved)
    • aws_iam_role + aws_iam_role_policy_attachment — AmazonEC2ContainerRegistryReadOnly
    • aws_iam_instance_profile — attaches role to instance
    • aws_security_group — ports 22, 80, 443 inbound; all egress
    • aws_instance — runs user_data.sh on first boot

    user_data.sh installs Docker and Docker Compose on the instance so it is ready to receive deployments immediately.

    Root variables reference

    Variable Default Override with
    aws_region us-east-1 -var="aws_region=eu-west-1"
    environment prod -var="environment=staging"
    app_name devops-challenge -var="app_name=myapp"
    vpc_cidr 10.0.0.0/16 -var="vpc_cidr=172.16.0.0/16"
    subnet_cidr 10.0.1.0/24 -var="subnet_cidr=172.16.1.0/24"
    availability_zone us-east-1a -var="availability_zone=eu-west-1a"
    ec2_instance_type t3.micro -var="ec2_instance_type=t3.small"
    key_name required -var="key_name=my-key"

    CloudWatch alarm

    The aws_cloudwatch_metric_alarm resource fires when:

    • Metric: CPUUtilization on the EC2 instance
    • Threshold: > 80%
    • Evaluation: 2 periods × 2 minutes = sustained high CPU for 4 minutes

    No SNS topic is wired up by default. To get notified, add an alarm_actions attribute pointing to an SNS topic ARN.
